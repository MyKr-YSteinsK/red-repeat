# RED:REPEAT 歌曲内容生成规范

本文档是 Song Edition source package、Validator、Compiler、Runtime 和 Timeline Debugger 共同使用的内容契约。字段和规则以当前代码为准；不满足契约的内容不能进入可消费的 Runtime。

## 1. Source package 目录

每首歌位于 `library/<song-id>/`。`<song-id>` 必须是小写 URL/filesystem-safe slug：

```text
^[a-z0-9]+(?:-[a-z0-9]+)*$
```

目录名必须与 `manifest.json.songId` 完全一致。根目录下以 `.` 开头的目录不会被发现。

```text
library/
└── <song-id>/
    ├── manifest.json       # required
    ├── lyrics.json         # required
    ├── timeline.json       # required
    ├── visual.json         # required
    ├── audio/
    │   └── source.<input-extension>   # required, exactly one
    ├── artwork/
    │   ├── cover.<input-extension>   # required, exactly one
    │   └── hero.<input-extension>    # optional, at most one
    └── features/
        └── *.md            # optional, zero or more
```

`manifest.json`、`lyrics.json`、`timeline.json`、`visual.json` 是 source contract 的必需 JSON 文件。`audio/source.*`、`artwork/cover.*`、`artwork/hero.*` 的 canonical 规则按文件名匹配，而不是按某一个固定扩展名匹配；实际媒体仍必须能被当前的 ffprobe/ffmpeg 或 sharp 处理。

`public/library-runtime/` 是 Compiler 生成的 Runtime 输出，不是内容编辑目录。不要直接编辑其中的 JSON 或媒体文件；修改 `library/<song-id>/` 后重新 validate/compile。

## 2. `manifest.json`

```json
{
  "songId": "first-light",
  "title": "First Light",
  "artist": "A Composer",
  "album": "Synthetic Sessions",
  "year": 2026,
  "intro": "A short introduction, at most 280 characters."
}
```

字段：

| 字段 | 必需 | 规则 |
| --- | --- | --- |
| `songId` | 是 | slug；必须等于歌曲目录名 |
| `title` | 是 | 非空文本 |
| `artist` | 是 | 非空文本 |
| `album` | 否 | 非空文本 |
| `year` | 否 | 非负整数 |
| `intro` | 否 | 非空文本，最多 280 字符 |

JSON object 是 strict contract；未定义字段会导致 `SCHEMA_INVALID`。

## 3. `lyrics.json`：Segment 内容

```json
{
  "segments": [
    {
      "id": "s001",
      "lyrics": "A line worth returning to",
      "translation": "一行值得反复回到的歌词",
      "layers": [
        { "id": "pronunciation", "label": "Reading", "text": "..." }
      ],
      "notes": [
        { "title": "Optional note", "body": "A high-value note." }
      ],
      "emphasis": "subtle"
    }
  ]
}
```

`Segment` 字段：

- `id` 必需，必须匹配 `^s[0-9]+[A-Za-z0-9_-]*$`；同一 `lyrics.json` 内必须唯一。
- `lyrics` 必需，canonical 原文，不能为空。
- `translation` 必需，当前产品契约要求每个 Segment 都有非空翻译。
- `layers` 可选；每一项需要非空 `id`、`label`、`text`。
- `notes` 可选；每一项需要非空 `body`，`title` 可选。不要为了填充结构强迫每句都有 notes。
- `emphasis` 可选，只能是 `subtle` 或 `strong`。

Segment 是 canonical 学习内容。它不携带真实时间；时间属于 Timeline 中的 Occurrence。同一 Segment 可以被多个 Occurrence 重复引用。

## 4. `timeline.json`：Section 与 Occurrence

```json
{
  "audioSourceHash": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
  "sections": [
    { "id": "verse-1", "label": "Verse 1", "startMs": 0, "endMs": 12000 },
    { "id": "instrumental", "label": "Instrumental", "startMs": 12000, "endMs": 16000 }
  ],
  "occurrences": [
    {
      "id": "o001",
      "segmentId": "s001",
      "sectionId": "verse-1",
      "startMs": 1000,
      "endMs": 3500,
      "playStartMs": 700,
      "playEndMs": 3900,
      "performanceNote": "Optional human performance note."
    }
  ]
}
```

### 4.1 `audioSourceHash`

`audioSourceHash` 是 canonical `audio/source.*` 文件的原始字节 SHA-256，必须是 64 位小写十六进制字符串。它不是编译后 M4A 的 hash，也不是 JSON 内容 hash。

计算方式：

```bash
npm run library:audio-hash -- <song-id>
```

该命令只读 `library/<song-id>/audio/source.*`，使用与 Validator/Compiler 相同的 canonical discovery 规则，打印 `songId`、`sourcePath` 和 `audioSourceHash`，不写 source package、Runtime 或网络资源。未知歌曲、缺失 source、多个 `source.*` 或读取失败都会以明确错误退出。

更换 source audio 后必须重新计算并确认 `timeline.json.audioSourceHash`。Validator 在 hash 不一致时报告 `TIMELINE_AUDIO_SOURCE_MISMATCH`；Compiler 在 Validator 失败时不会生成新的 Runtime。

### 4.2 Section

Section 表示音频中的结构段，可以是 Verse、Chorus、Bridge，也可以是没有任何歌词 Occurrence 的纯器乐段。

- `id` 必需且唯一，匹配 `^[a-z][a-z0-9_-]*$`。
- `label` 必需且非空。
- `startMs`、`endMs` 必须是非负整数毫秒，并满足 `startMs < endMs`。
- 时间区间使用半开区间 `[startMs, endMs)`：等于 `endMs` 的时刻已经离开该 Section。
- `sections` 数组是 source order；相邻声明的 `startMs` 不得倒退。
- Section 之间不得 overlap；合法 gap 可以存在，Section 不要求无缝覆盖整首音频。
- 纯器乐 Section 的 `occurrences` 数量可以为零。

### 4.3 Occurrence

Occurrence 表示一个 Segment 在真实时间轴上的一次出现。

- `id` 必需且唯一，匹配 `^o[0-9]+[A-Za-z0-9_-]*$`。
- `segmentId` 必须引用 `lyrics.json` 中存在的 Segment。
- `sectionId` 必须引用 `timeline.json` 中存在的 Section。
- 所有 timing 字段都是非负整数毫秒。
- `performanceNote` 可选，为非空文本。

Occurrence 的两个时间范围必须满足：

```text
startMs / endMs
= 实际演唱范围

playStartMs / playEndMs
= 练习播放范围，可包含 lead-in / tail

0 <= playStartMs <= startMs < endMs <= playEndMs
```

实际范围 `[startMs, endMs)` 必须完全落在所属 Section 内。练习范围可以跨越 Section 边界，这允许在句子前后保留自然的 lead-in 或 tail。

不同 Occurrence 的 actual range 可以 overlap；Resolver 会在同一时刻保留所有 active Occurrences，并按 actual `startMs`、source index 得出 primary/chronological 顺序。不要为了消除重叠而合并重复 Segment。

## 5. `visual.json`

```json
{
  "recommendedTheme": "liner",
  "mood": ["restrained", "night"],
  "motifs": ["distance"],
  "energy": "restrained",
  "density": "balanced",
  "motion": "slow",
  "coverTreatment": "editorial",
  "sectionCues": [
    { "sectionId": "verse-1", "cue": "isolate" }
  ]
}
```

字段和枚举：

- `recommendedTheme` 必需：`liner`、`cinema`、`nocturne`。
- `mood`、`motifs` 可选，均为非空文本数组。
- `energy` 可选：`quiet`、`restrained`、`balanced`、`intense`。
- `density` 可选：`sparse`、`balanced`、`dense`。
- `motion` 可选：`still`、`slow`、`moderate`。
- `coverTreatment` 可选：`clean`、`editorial`、`atmospheric`、`abstracted`。
- `sectionCues` 可选；`sectionId` 必须引用现有 Section，`cue` 可选值为 `isolate`、`expand`、`compress`、`brighten`、`darken`、`suspend`、`dissolve`、`echo`。

Visual 是 semantic art direction，不是任意视觉 DSL。当前 contract 不支持 custom CSS、JS、HTML、absolute coordinates 或任意布局指令。

## 6. Feature Markdown

Feature 是可选内容；没有 `features/` 或没有 `.md` 文件的歌曲仍然是有效 Song Edition。Compiler 按文件 basename 生成 Feature id，并以内容 hash 生成 Runtime 文件名。

Validator 会检查所有 `features/*.md` 中的 Segment 引用。当前支持的 Markdown 范围是：

- `#` 到 `######` heading；
- 普通 paragraph；
- 连续的 `-`、`*` 或 `+` 无序列表；
- `**bold**`、`__bold__`；
- `*italic*`、`_italic_`；
- `[[segment:<segment-id>]]` cross-reference。

`[[segment:<id>]]` 必须引用已有 Segment；Runtime 中它会成为跳转到该 Segment 首个 Occurrence 的按钮。不要在 Feature 中假设未实现的完整 Markdown、HTML 或脚本能力。Feature 加载失败时，当前 Runtime 会保留歌词可用性并单独显示 Feature error。

## 7. Media 与 Runtime 输出

### 7.1 Audio

Compiler 使用 ffprobe 检查 source audio，并将其转换为 Runtime 音频：

```text
container: m4a
codec: AAC-LC
bitrate: 192 kbps
channels: 2
sampleRate: 44100 或 48000
```

Runtime `audio.sourceHash` 保留原始 source 文件的 hash，`audio.runtimeHash` 是生成的 M4A 文件 hash；两者语义不同。Compiler 还会检查最大的 Section end 或 Occurrence playEnd 是否超过探测到的音频时长，允许的 tolerance 为 100ms。

### 7.2 Artwork

必需的 `artwork/cover.*` 会生成 cover-small（最大宽度 640）和 cover-large（最大宽度 1600）WebP。可选的 `artwork/hero.*` 会生成 hero-large（最大宽度 1920）WebP。hero 缺失是 warning，不是 error；cover 缺失或同类文件多于一个是 error。

### 7.3 Runtime contract

Compiler 生成 `public/library-runtime/` 下的 `catalog.json`、每首歌的 `edition.<contentHash>.json`、hash-named lyrics/timeline/visual/feature 资源和处理后的媒体。Runtime URL 必须以 `/library-runtime/` 开头。

Runtime Edition 至少包含：

- `contractVersion: 1`；
- `contentHash`；
- `song` metadata；
- `lyricsUrl`、`timelineUrl`、`visualUrl`；
- Feature descriptors；
- audio descriptor（URL、source/runtime hash、duration、format）；
- artwork descriptor（cover small/large，可选 hero）。

浏览器只通过 Runtime Client 读取这些生成资源，再由 assembler 建立 `Segment → Occurrence → Section` 的消费模型。Catalog metadata、Edition metadata 和 Visual theme 不一致会阻止装配。

## 8. Validator 与 Compiler 工作流

推荐顺序：

```text
1. 准备 library/<song-id>/ source package
2. npm run library:audio-hash -- <song-id>
3. 将输出 hash 写入 timeline.json.audioSourceHash
4. npm run library:validate
5. npm run library:compile
6. npm run dev / npm run build
7. 用 Song Edition 和 Timeline Debugger 检查内容与听感
8. Debugger 导出完整 timeline.json
9. 手动替换 library/<song-id>/timeline.json
10. 再次 library:validate
11. 再次 library:compile
```

`library:validate` 默认读取当前工作目录下的 `library/`。它会报告 JSON/schema、required source、canonical media、audio hash、Segment/Section reference、Section order/overlap、Occurrence containment、Visual Section cue 和 Feature Segment reference 问题。缺失 hero 只产生 `NO_HERO_ARTWORK` warning。

`library:compile` 先执行同一 Validator；任何 validation error 都会阻断编译。通过后再进行音频/图片转换、结构化资源 hash、Feature 编译和 Runtime Edition 生成，并以临时目录替换 Runtime 输出，避免留下半成品。

常见需要优先处理的 diagnostic code：

| code | 含义 |
| --- | --- |
| `MISSING_SOURCE_FILE` / `JSON_PARSE_ERROR` / `SCHEMA_INVALID` | required JSON 不存在、不可解析或不符合 schema |
| `MISSING_AUDIO_SOURCE` / `AMBIGUOUS_AUDIO_SOURCE` | canonical `audio/source.*` 缺失或不唯一 |
| `MISSING_COVER_ARTWORK` / `AMBIGUOUS_COVER_ARTWORK` | canonical cover 缺失或不唯一 |
| `TIMELINE_AUDIO_SOURCE_MISMATCH` | Timeline hash 与当前 source audio 不一致 |
| `UNKNOWN_SEGMENT_REFERENCE` / `UNKNOWN_SECTION_REFERENCE` | Timeline 引用了不存在的内容 |
| `SECTION_OUT_OF_ORDER` / `SECTION_OVERLAP` | Section source order 或时间边界非法 |
| `OCCURRENCE_OUTSIDE_SECTION` | actual Occurrence 超出所属 Section |
| `UNKNOWN_FEATURE_SEGMENT_REFERENCE` | Feature cross-reference 指向不存在 Segment |
| `TIMELINE_EXCEEDS_AUDIO_DURATION` | Timeline practice/Section 边界超出音频时长 tolerance |

## 9. Timeline Debugger 与人工 timing 流程

开发模式下可直接打开：

```text
/#debug=timeline&edition=<song-id>
```

该入口不出现在普通用户导航中；生产构建对该 hash fail closed，回到 Library。Debugger 复用现有 Audio Engine，不创建第二个生产 `HTMLAudioElement`、Web Audio 或另一套 range/loop 逻辑。

Debugger 会加载 catalog、Runtime Edition、lyrics、timeline、visual，并在内存中创建 working copy：

- Occurrence：`playStartMs`、`startMs`、`endMs`、`playEndMs` 可按 ±50/±100ms 调整；可 seek 每个边界、replay practice range、play actual range、前后导航。
- Section：`startMs`、`endMs` 可按 ±50/±100ms 调整；可 seek Section 起止并执行 Debugger 专用 `Play Section`。纯器乐 Section 即使没有 Occurrence 也可以 audition。
- 每次调整即时检查 schema、Occurrence timing、Section source order/overlap 和 actual containment。输入不会被自动 clamp、reorder 或移动关联 Occurrence；无效时明确显示 field path，并阻断 export。
- `Reset selected Occurrence`、`Reset selected Section` 和 `Reset all changes` 恢复 loaded baseline。
- Export 生成完整 `timeline.json`，保留 sections/occurrences source order，使用 2-space JSON + trailing newline，并写入当前 Runtime audio source hash。可以 Copy 到 clipboard 或 Download 为 `timeline.json`。

浏览器不会自动覆盖仓库文件，也不会向 localhost backend 发写请求。导出后由人工替换 source 文件，再执行 validate/compile。

Debugger 的 `Play Section` 与普通 Song Edition 的 `Section Loop` 语义不同：后者基于 lyric Occurrence 的 practice envelope，没有 lyric Occurrence 时保持 unavailable；前者只是 Debugger 对 Section `[startMs, endMs)` 的 audition。

## 10. Timing 来源优先级与内容质量边界

时间戳不要凭空猜测。推荐优先级：

1. 用户已有的 synced lyrics 或 timestamps；
2. 本地 alignment 工具；
3. 人工 Timeline Debugger 听感修正；
4. GPT 可以协助 Segment 语义切分，但不得捏造毫秒 timing。

内容生产的稳定边界：

- translation 是当前 Segment 的必需字段；
- Segment 是 canonical 内容，Occurrence 只表达出现和时间；
- notes 应稀疏且有高价值，不为填结构而生成；
- Feature 是 optional，不要求每首歌都有；
- Visual 只使用当前 schema 支持的 semantic fields；
- research/source 信息若尚未在 schema 中正式定义，不要虚构 citation schema；
- source audio 被替换后必须重新 hash、validate、compile，并重新听取关键边界。
