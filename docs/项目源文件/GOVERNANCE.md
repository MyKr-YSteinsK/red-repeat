# 工程与交付约定

## 从哪里接手

| 入口 | 职责 |
| --- | --- |
| GPT Project Main | 与用户比较产品和架构方案、细化近期阶段、组织正式交接、审查验收和重大取舍。 |
| Codex Native | 依据直接指令和仓库执行调查、局部设计、开发、验证和已授权交付。在边界内自主推进。 |
| Codex Hub | 汇合多个有效任务时核对来源、编号、依赖、写入范围及共用资源。共用检查可复用，验收分别记录。 |

用户决定重大方向、数据边界、不可逆操作和必要验收。正规化或内部重构可以按任务权限推进。
版本化配置、公开数据、生产发布和冻结方案各有自己的授权。授权范围内把已核实的实质变化写回原有
项目文件，避免按任务堆积过程日志。路径、编号、产品状态及部署身份使用实际证据。

## 任务交接

简单工作在对话给出目标与边界。正式交接沿用 `# RED-Plan-<n> — 中文标题`。有创建授权、且正文适合目标
仓库可见性时，默认把完整 Markdown Plan 放入目标仓库 GitHub Issue，交付 Issue 链接与短 Prompt。
包含受限内容或 Issue 不可用时，使用用户提供的完整正文、可读文件或其他已授权私有渠道。
无需为已有有效任务分配新编号。仓库外副本按用户指定；历史 Plans 和 Handoffs 作为证据单独存放。

正式 Plan 写清项目、目标、真实工作区、适用基线、硬边界、验收、允许的 Git/发布动作及交付。
接到结构化 Song Handoff 后，先读正文、校验来源、版本及必要清单，按已批准的正文、字段、映射和精确素材集成。
待确认的读音、译文、时间点、素材权利或身份冲突按其输入状态处理。历史审稿和候选文章不授予集成许可。

新对话从根 `AGENTS.md`、[项目合同](PROJECT.md)、[当前状态](STATUS.md)恢复。
回执注明实际来源、结果、变更、关键验证、未运行项和 Git 交付。工作完成、证据接受和阶段升级分别判断。
本机路径精确写在任务输入；公开资料只携带需要的项目路径。

## 数据和材料

公开、获批的 Song Edition 源放于 `library/<song-id>/`。受限研究、来源和待验输入放于
`.private/`。仅按任务权限访问和处理两类材料。开发输出使用[运行手册](RUNBOOK.md)中列出的可重建目录；
临时工作用独立 `%TEMP%\red-repeat-<task-id>-<unique>\`。本轮约定待手动移除的旧文件移到
仓库内 `docs/delete/` 并保留来源路径，该目录忽略于 Git 和 lint。
`D:\CS\temp\Red-Repeat\` 是用户历史输入，改动其中的材料需要当前任务的具体授权。
临时产物若无法安全清理，按任务标识保留在 `D:\CS\temp\RED-REPEAT-CODEX-RESIDUALS\<task-id>` 并交代原因。

## 验证和真实使用证据

按风险选最短有效检查。文档检查入口、引用和事实。代码运行受影响测试和有价值的本地真实浏览器路径。
内容、Schema、Compiler 或时序涉及源验证与编译；音频变更单独核对源 SHA-256。
离线和本机状态变更需匹配现有数据、身份、取消／回退及失败后可用性。静态 PWA 产物与真实设备上的已安装应用分别验收。

常规低风险 UI、内容和现有生命周期日常体验标为 `POST-DEPLOY OBSERVATION`。任务明确要求、
高风险数据／持久化／身份／发布、PWA 更新生命周期实质变化、音频身份不明、准备声称
`Calibrated Timing` 或最终听感，或部署后无法安全纠正时，按 D-016 设相应 `BLOCKING USER CHECK`。
D-020 允许音源、结构和明显串句检查通过的 Provisional Timing 先用，状态保持未校准。
自动化报告标明环境和实际证据，音频与真机仅按执行范围报告。

## Git 与发布

- 工作分支和工作树按任务选择，保留原有未归属改动。非发布的远端同步可用维护分支。
  `main` 的推送触发质量检查，成功后进入 GitHub Pages。核对任务对推送、合并和部署的授权。
- 正式 Plan 满足范围、必要验证、无阻塞门槛且允许推送时，可以按现有合同完成、提交并推送其授权分支。
  远端分歧、未归属改动、失败验收、权利不明或高风险冲突先解决受影响边界。分支同步用实际远端 ref 核对。
- 维护、纯文档或内部等价重构通常 `no-version`。发布须按[版本发布规范](../版本发布规范.md)处理
  package、ledger、tag、构建 SHA、CI、Pages 和线上身份。tag 指向真实产品实现提交，部署 SHA 可属于随后
  经验证的元数据提交。历史不一致留证据。禁止 force push 或覆盖 tag。

面向本项目的回执、正式 Plan 和报告默认中文，路径、命令、路由、标识符及精确引文保留原样。
