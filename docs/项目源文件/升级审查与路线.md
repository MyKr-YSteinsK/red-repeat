### 解析入口与审计边界

- `src/library/schema.ts` 定义源字段的 trim、strict、ID、时间与 Ruby 细化。`runtime-schema.ts` 描述 contract v3 的 Catalog 与 Edition。Library validator 逐文件读取本地源包，JSON 解码后依次做结构与跨文件引用检查，诊断记录字段位置。编译器与交付检查读取已生成的描述文件，失败会中止该次交付。
- 浏览器 Runtime Client 将逻辑路径解析到应用 base 下，按 Catalog、Edition、Lyrics、Timeline、Practice 分别解析同源响应和本机缓存。发布者可改变正式资源，既有客户端也可能读到损坏的缓存。无效 Catalog 缓存可失效重取，歌曲解析错误保留资源路径与类型，界面提供重试。Feature 正文走文本读取。
- 下载器校验资源后再登记完整 manifest，读取 v1 与 v2 的快照时复核 Edition 和目录项。Timing Debugger 的 Timeline 校验、audio-hash CLI 的 songId 校验也复用相应 Schema。个人备份导入走自己的白名单与域解析，接收文件这一操作本身并不调用歌曲 Zod Schema。
- `npm ls zod --all` 在两个版本均显示一个解析版本，直接生产依赖与开发用 eslint-plugin-react-hooks、zod-validation-error 共用它。4.6.6 为公告列出的修复版本。选择此版本限制了锁文件变更，沿用了现有调用 API。[上游安全公告](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5)
