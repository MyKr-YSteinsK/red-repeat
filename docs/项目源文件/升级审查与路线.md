# 升级审查与路线

首轮构建与 Zod 升级已由 [RED-Plan-93](https://github.com/MyKr-YSteinsK/red-repeat/issues/2) 和 [RED-Plan-94](https://github.com/MyKr-YSteinsK/red-repeat/issues/3) 授权实施。其余工作包冻结，待用户确认。本文基于 `main@cfa91fb`、现有测试和接手分支的本地构建审查。
现有产品与数据合同见[项目合同](PROJECT.md)，本轮已做的等价整理和验证见[当前状态](STATUS.md)。
下列工作包可以独立选择。候选方案、度量口径和验收设计随实际任务确认。

## 建议顺序与验收

### 1. 依赖与构建可靠性

优先起两个独立小任务。依赖任务核对锁文件直接与传递链，先评估 Zod 升级是否改变解析或错误边界。
之后处理 Vite／媒体／测试工具，按相近风险分批升级。候选版本逐个对比旧版接受的合法 JSON、参考错误场景、
六曲编译产物标识符和正式子路径构建。对受影响包留一个可复核审计快照，必要时缩小 dev 服务暴露面。
退出条件是锁文件可重建、匹配检查通过，仍有告警时能解释具体剩余入口及影响。

构建任务先把 staging 隔离出 `public/`，比较同盘 rename、有界备份与独立最终校验方案。
验收覆盖中断、失败、旧输出可用、重复生成与并发冲突，并检查 `dist/` 只含经验证的 Runtime。
随后再决定是否减少 CI 重复步骤。复用 Pages 产物时核对生成任务、artifact、部署和 `version.json`
指向同一已验 SHA，继续检查根路径和 `/red-repeat/` 表现。可用独立提交回退流程变更，保留既有发布链作为回退。

### 2. Catalog 与页面结构

以路由请求为边界整理 App，明确一次导航如何取消、谁接收结果和返回时如何恢复锚点。
先检查 warm entry 的 AbortController 是否在依赖切换或快速前后退时留下已处理 href 与旧页面；
用真浏览器及定向组件测试确认是否存在可复现症状。保持 Catalog 搜索、离线筛选、排队状态和 DOM 焦点。
分离下载状态订阅与展示时保留 document 级任务 owner，避免离开页面意外取消任务或重启下载。

列表数据扩大后比较逐首检查、分批核验、按可见区调度。只有实测数量和延迟证明收益时再上虚拟化。
验收覆盖冷启动、H1 活动而 Catalog 指向 H2、网络失败、快速返回及点击/键盘进入。
验收信号是目标视图正确、无状态反转、取消后旧任务无权更新新页面。
每次只迁一个子面，便于按提交回退。

### 3. 移动交互与视图组件

先截取当前 Practice dock、Segment Picker、Full Song 底栏、Explain 文章导航和 Settings 的代表页面。
以小中大屏、短长歌词、Ruby 显示、横屏、输入焦点、reduced motion 为场景拆分 cascade。
把 CSS 移到各屏 owner 附近，保持相同选择器优先级与断点次序，逐步抽出 pane。
个人备份、Timing 保留记录和更新提示先拆展示，事务留在已有域。
DOM/视觉差异须能解释为已批准变化；iPhone/Safari 与 installed-PWA 验证安全区、触摸、滚动与遮挡。
可以在同一基线验证后另审界面设计方案。

### 4. 播放协调与资源效率

保留现有媒体适配器，对用户命令、当前播放操作的标识、浏览器事件和最终意图做受控日志。
先覆盖连续播放跨模式、点击练习转 bounded、试听自然结束、显式取消、换歌后迟到的播放事件、seek 及固定速率。
只有明确可重现的竞争问题才引入更显式的 session 状态模型，必要时用当前实现与候选跑相同事件表。
断点以实际最后位置、播放意图、速率和归属歌曲判断；听感以同一音源的实际短句采用独立证据。

同时采集冷／热／离线进入、慢网输入响应、峰值内存、请求及解码次数。标出测量条件、曲目、样本数和对照值。
先试 route chunk、图片或订阅隔离，继续让可选 Feature 脱离 Practice 就绪链。
保留解析复用和取消合同。若瓶颈横跨多 owner，再评估 `SongRepository` 与 `ResourceScheduler` 的实际收益、
与现有 Cache Storage 的边界及最小替换路径。

### 5. 本地能力与数据演进

先用脱敏或合成数据建立旧版身份、H1/H2、配额、失败补偿和跨标签页用例。分别验收 Timing、最近会话、
队列、默认进度／速率、显示偏好、备份和离线 manifest；对照可读取性、默认保留与恢复条件。
无损拆分写入层后，再比较三条数据路线。

| 候选 | 价值 | 用户需决定 |
| --- | --- | --- |
| 保持现有分域存储 | 成本最低，先改善诊断、导出和可验证恢复。 | 是否需要集中查看各域的陈旧或冲突原因。 |
| 特定域迁入 IndexedDB | 提供该域的多记录事务和索引，便于维护与检索。 | 迁移和回退窗口、已存数据的跨版本兼容，以及无法写入时的旧数据保护。 |
| 研究部分内容修订的身份兼容 | 解决仅改文章／译文时既有本地数据的可用性问题。 | 哪些域允许何种证据触发兼容。保持音频和 Timeline 完整身份、明确用户选择与可逆演练。 |

允许自动重绑定的范围由用户指定，D-028 的现行严格行为继续适用于当前实现。涉及 Worker 策略、下载协议或
真实本机数据迁移时，先验证故障下仍可读取完整 H1，再确认实际目标客户端上旧会话保持与下一次启动接管。

### 6. 供稿与歌曲体验

建立旁路的内容审阅预览，按 Segment／Occurrence、Feature 引用、音源 SHA、Timeline 和变更后的 Edition
给出差异。让作者能核对编辑改动和身份后果，可复用判定进入既有歌曲规范。
选一首待校准歌曲试行显式证据表，记录实际 onset、end、重叠或串句及审听覆盖。最终校准通过
Timing Correction Export 对照并只应用通过身份核对的字段。用户可验收候选原文和音频权利。

产品体验可并列试三条路径，各选小样本比较是否更快回到想练的句子。

- **跨曲找句**以本地歌词、读音和已获批的译文检索精确 Occurrence。按版权边界选择是否生成可下载索引。
  原型验收包括多处同句、Unicode、切换筛选与离线命中，先量索引大小和首开代价。
- **主题学唱清单**把用户选中的少量句或段串成可编辑路线，借用现有队列的定位与恢复，进度保持显式意图。
  用户操作完成和移除，D-025 下不建立学习评分或掌握推断。
- **按当前句读讲解**利用已有 Feature 引用，提供简洁的解释入口与原位返回。试验应检查阅读打断、滚动
  焦点和试听撤销，以及长文在窄屏上的触达。用现有数据小范围观察后再决定是否扩展编辑结构。

### 7. 交付质量与长线选择

若用户希望全面重构，建议顺序是可重复发布和依赖 → 页面与播放特征测试 → 按 owner 垂直切片 →
局部性能与内容工具 → 数据迁移或新产品。以每一片的功能对等、回退能力和实际维护成本决定是否继续。
保留 React/Vite 与静态源是起步方案。另一条候选是先在一个非关键页面对比新构建或新状态方案；
只有真机、产物、编译复杂度和发布兼容有净收益时再讨论整站迁移。

可把本次浏览器链路提炼为可重复的 smoke，分别保留组件、Chromium、iOS/installed-PWA 和人耳证据。
上线候选要能从版本、tag、部署 SHA 和静态子路径联合定位。各路线上已验证的行为通过当前源与测试写回
[当前状态](STATUS.md)，升级选项的选择由用户确认后形成单独任务。
